## 🆕 v1.0 (دور ممیزی عمیق RBAC + کانال ویرایش) — تغییرات این دور:
  + RBAC — پاک‌سازی کامل تعریف کاربر و دسترسی ادمین (یافته‌ی ممیزی: قبلاً ناتمام بود):
    · نقش «owner» (مالک سایت) بالاتر از admin معرفی شد؛ seed و install.sh حساب
      admin را owner می‌کنند و دیتابیس‌های قدیمی با UPDATE idempotent مهاجرت می‌شوند
    · src/lib/rbac.ts — تک منبع حقیقت نقش‌ها/تب‌های واگذارشدنی (قبلاً در ۴ فایل تکرار
      شده بود و بین UI و سرور ناهماهنگی داشت)
    · ادمین دیگر نمی‌تواند ادمین/مالک دیگری را بسازد، ویرایش یا حذف کند
      (canManageTarget — فقط کاربران عادی)؛ ساخت ادمین فقط با مالک
    · حساب مالک از پنل قابل حذف/تنزل/غیرفعال‌سازی نیست
      (owner_account_immutable / owner_cannot_be_deleted / cannot_deactivate_owner)
    · تغییر رمز در /api/admin/security برای مالک هم کار می‌کند (قبلاً 404 می‌داد!)
    · شمارش «آخرین ادمین فعال» شامل owner شد — قفل شدن پنل ناممکن است
    · UI آگاه از نقش: برچسب «مالک 👑»، دراپ‌داون نقش فقط برای مالک، دکمه‌های
      ویرایش/حذف فقط داخل محدوده‌ی اختیار بیننده رندر می‌شوند
  + کانال ویرایش از دور (v1.0 rev2) — روی کانال نگهداری قبلی:
    · MAINTENANCE_EDIT_TOKEN (حداقل ۴۸ کاراکتر) با هدر X-Maintenance-Edit-Token —
      timing-safe + fail-closed؛ install.sh تولید و یک بار چاپ می‌کند
    · actionهای ویرایشی سفید-لیست: texts.set، settings.set، nav.*، clip.*،
      equipment.set، content.set-visible، export-all، help-edit، version
    · هر ویرایش در SecurityLog با IP و target ثبت می‌شود؛ کلیدهای محرمانه هرگز
      قابل نوشتن/خواندن نیستند؛ rate limit ۶۰/۵دقیقه
    · scripts/maintenance.sh با --data؛ scripts/sync-from-online.sh +
      scripts/apply-online-export.mjs — همگام‌سازی دقیق آفلاین↔آنلاین
  + تست دودی scripts/smoke-rbac.sh — ۲۸ چک واقعی روی بیلد production: همه سبز
    (سلسله‌مراتب نقش‌ها، immutability مالک، تغییر رمز مالک، دو توکن، export-all)
  + کامنت‌گذاری فارسی سرصفحه برای ۳۱ فایل — پوشش کامل سورس
  + مستندات: docs/TUTORIAL_FA_v1.docx (۱۴ فصل) + docs/AUDIT-REPORT-FA_v1.docx
    (گزارش ممیزی فارسی) — داخل zip انتشار

⚠️ نکته‌ی تاریخچه: شماره‌های داخلی قبلی (V17.x/V18.x/v1.1.x) به‌عنوان revision

# خروجی رسمی: ehsan-site-v1.0-<تاریخ-شمسی>.zip (مثلاً ehsan-site-v1.0-1405-08-24.zip)
unzip ehsan-site-v1.0-*.zip
cd personal-site

ورود ادمین:
  http://YOUR_IP/user-login          ← پورت 80 (nginx جلوی سایت است)
  username: admin
  password: (توسط install.sh چاپ می‌شه — رمز تصادفی؛ حداقل ۱۲ کاراکتر)
  ⚠️ رمز فقط یک بار موقع نصب نمایش داده می‌شه — یادداشتش کن!
     (کپی امن: sudo cat db/.admin-initial-password.txt)
  ⚠️ حتماً از پنل → تنظیمات → تغییر رمز عوض کن!

================================================================
  کانال نگهداری و ویرایش اختصاصی (v1.0 rev2)
================================================================
install.sh دو توکن تولید می‌کند و یک بار چاپ می‌کند:
- MAINTENANCE_TOKEN (خواندن) — کپی امن: sudo cat db/.maintenance-token.txt
- MAINTENANCE_EDIT_TOKEN (ویرایش، ≥۴۸ کاراکتر) — sudo cat db/.maintenance-edit-token.txt

روی خود سرور:
  cd /home/ehsan/personal-site
  bash scripts/maintenance.sh status
  bash scripts/maintenance.sh backup

از دور (هر جا):
  export MAINTENANCE_TOKEN=... MAINTENANCE_URL=https://ehsanmorad.ir
  bash scripts/maintenance.sh security-logs

actionهای خواندن: status | db-stats | security-logs | messages | chats | backup | help
actionهای ویرایش (هدر دوم لازم): texts.get/set | settings.get/set | nav.* | clip.* |
  equipment.get/set | content.get | content.set-visible | export-all | help-edit
امنیت: دو هدر X-Maintenance-Token + X-Maintenance-Edit-Token با timingSafeEqual —
fail-closed بدون توکن؛ rate limit ۶۰/۵دقیقه؛ همه‌ی فراخوانی‌ها در SecurityLog ثبت می‌شوند.
همگام‌سازی آفلاین↔آنلاین: bash scripts/sync-from-online.sh && node scripts/apply-online-export.mjs <file>

================================================================
  تنظیم reCAPTCHA (بعد از نصب)
================================================================

  1. https://www.google.com/recaptcha/admin برو
  2. یه سایت v2 ثبت کن (دامنه‌ات رو اضافه کن)
  3. Site Key و Secret رو در .env بذار:
       RECAPTCHA_SECRET="<secret-key>"
       NEXT_PUBLIC_RECAPTCHA_SITEKEY="<site-key>"
  4. sudo systemctl restart personal-site

⚠️ بدون reCAPTCHA، فرم تماس کار نمی‌کنه!

================================================================
  انتقال سایت به سرور دیگر (VPS → VPS)
================================================================

روی سرور قدیمی:
  bash scripts/export-site.sh
  → ~/site-migration-<timestamp>.tar.gz می‌سازه (snapshot دیتابیس + .env + بک‌آپ‌ها)

کپی به سرور جدید:
  scp ~/site-migration-*.tar.gz root@NEW_SERVER_IP:/root/

روی سرور جدید (اول نصب تمیز):
  wget .../install-v1.1.zip && unzip && cd personal-site && sudo ./install.sh
  sudo bash scripts/import-site.sh /root/site-migration-<timestamp>.tar.gz

import-site.sh:
  - دیتابیس رو با owner امن (ehsansite) نصب می‌کنه
  - .env رو MERGE می‌کنه (DATABASE_URL جدید می‌مونه؛ secretها و tokenهای
    قدیمی برمی‌گردن)
  - apply_schema.py اجرا می‌شه (heal کردن schema drift)
  - سرویس رو start می‌کنه و admin رو verify می‌کنه

چک‌لیست بعد از مهاجرت:
  □ Webhookها رو برای دامنه‌ی جدید ثبت کن (Bale/Telegram setWebhook)
  □ sudo certbot --nginx -d YOUR_DOMAIN
  □ دامنه‌ی جدید رو تو console گوگل reCAPTCHA اضافه کن
