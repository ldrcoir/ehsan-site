## 🆕 v1.0 rev3 (ممیزی مجدد با ۴ worker + کانال رمزنگاری‌شده) — تغییرات این دور:
  + 🔐 کانال نگهداری حالا واقعاً رمز می‌شود (AES-256-GCM):
    · MAINTENANCE_ENC_KEY (۶۴ hex = ۳۲ بایت) — install.sh تولید و یک بار چاپ می‌کند
    · درخواست و پاسخ هر دو رمز می‌شوند: {"enc":"v1","data":"<b64(iv|ct|tag)>"}
    · داخل پاکت: ts (±۵ دقیقه) + nonce یک‌بارمصرف — replay و پیام کهنه رد می‌شوند
    · سرور وقتی کلید دارد، درخواست متنیِ خام را با 426 رد می‌کند (fail-closed)
    · کلاینت مرجع: scripts/maintenance-enc.mjs — maintenance.sh و
      sync-from-online.sh و smoke-rbac.sh خودکار رمز می‌کنند
    · تست واقعی: status رمز → ok؛ plaintext → 426؛ replay → 400؛ ts کهنه → 400
  + 🔐 امنیت (یافته‌های ممیزی SEC):
    · مقایسه‌ی توکن نگهداری روی digest SHA-256 — حتی طول توکن لو نمی‌رود
    · clear_logs فقط owner + رکورد «security_logs_cleared» باقی می‌ماند
      (قبلاً کل تاریخچه‌ی امنیتی با یک POST بی‌اثر و بی‌ردپا پاک می‌شد!)
    · خواندن ai.* (system prompt چت) برای کاربر limited بسته شد — هم‌تراز با نوشتن
    · nav href اعتبارسنجی سمت سرور (ضد javascript:/data:)
    · بدنه‌های خطای providerها bounded read (ضد OOM)
    · IP لاگ webhookها از هدرهای جعلی به getClientIpSafe + سقف طول
    · سقف سخت mapهای rate-limit چت + take:200 لیست کلیپ‌ها
    · خطاهای bulk_import تجهیزات generic شد (لو نرفتن نام ستون‌ها)
    · حالت TRUST_PROXY اشتباه: سقف bucket سراسری لاگین 30/۱۵د + هشدار پررنگ
  + 🛠 پنل ادمین (یافته‌های PANEL):
    · owner حالا در تب کاربران دکمه‌ی ویرایشِ ردیف خودش را دارد (سرور از قبل مجاز بود)
    · حذف کاربر/جلسه‌ی چت/پیام چت بازخورد موفقیت می‌دهد (قبلاً بی‌صدا بود)
    · دو شمارنده‌ی بلاک‌شده و رویدادهای ۲۴ساعت در تب امنیت نمایش داده می‌شوند
    · تب قواعد AI برای کاربر limited پنهان می‌شود (قبلاً 403 دیرهنگام می‌گرفت)
    · دلیل غیرفعال‌سازی (deactivatedReason) از UI جمع می‌شود
    · خطای toggle provider بی‌صدا نبود؛ IP regex UI با سرور هم‌سو شد
    · دکمه‌ی «همه خوانده شد» برای پیام‌ها + جستجوی کاربران/لاگ‌ها (سمت کلاینت)
  + 🐞 باگ‌های runtime (یافته‌های BUG):
    · چت: ساعتِ مرجع poll همیشه از serverTime — دیگه با ساعتِ جلوِ کلاینت
      پاسخ‌های ادمین/AI برای همیشه گم نمی‌شوند
    · فرم تماس: getResponse گارد شده — دکمه‌ی submit دیگر برای همیشه قفل نمی‌شود؛
      time-trap سمت کلاینت — پیام دیگر بی‌صدا دور ریخته نمی‌شود
    · واترمارک canvas از حلقه‌ی RAF بیرون کشیده شد (۳ کامپوننت — ۶۰ promise/ث کمتر)
    · panel_lang از localStorage اعتبارسنجی می‌شود — داشبورد دیگر سفید نمی‌شود
    · جستجوی ArchiveGrid فیلدهای آلمانی + خلاصه‌ها را هم می‌گردد
    · ترمینال تعاملی: دستور admin → /user-dashboard (لنگر #admin وجود نداشت)
    · کش per-lang زبان‌ها — تعویض زبان دیگر متن زبان قبلی را فلش نمی‌کند
    · رشته‌های فارسی‌تنها سه‌زبانه شدند (کلیپ‌ها، یادداشت/تگ پیام‌ها، دکمه‌ی بستن)
    · ایمیل/URL داخل پنل RTL با dir=ltr — دیگر به‌هم نمی‌ریزند
  + 📦 استقرار (یافته‌های DEPLOY — جلوی نصبِ خراب گرفته شد):
    · zip رسمی حالا standalone است (server.js + node_modules + .next/static) —
      قبلاً zip فقط-سورس بود و install.sh روی سرورِ تازه crash-loop می‌کرد!
    · install.sh: fail-fast با پیام شفاف اگر standalone نباشد
    · bcryptjs حالا داخل standalone build است (seed ادمین روی نصب تمیز fatal نمی‌شود)
    · install.sh re-run دیگر کانفیگ TLS certbot را بازنویسی نمی‌کند
    · sync-from-online.sh و smoke-rbac.sh: shebang به خط اول منتقل شد (خطای // برطرف)
    · package-v1.sh: گروه‌بندی find اصلاح شد — قبلاً به‌خاطر تقدم عملگرها الگوهای
      *.db و *.db-* هرگز حذف نمی‌شدند + گارد نهایی فایل‌های توکن/کلید اضافه شد
  + تست: scripts/test-harness.sh — smoke کامل ۲۸/۲۸ سبز روی بیلد production
    + ۵ تست کانال رمز — همه سبز (۴ worker: امنیت/پنل/باگ/استقرار + تست واقعی)

  تنظیم reCAPTCHA (بعد از نصب)

  1. https://www.google.com/recaptcha/admin برو
  2. یه سایت v2 ثبت کن (دامنه‌ات رو اضافه کن)

================================================================
  انتقال سایت به سرور دیگر (VPS → VPS)
================================================================

روی سرور قدیمی:
  bash scripts/export-site.sh
  → ~/site-migration-<timestamp>.tar.gz می‌سازه (snapshot دیتابیس + .env + بک‌آپ‌ها)

کپی به سرور جدید:
  scp ~/site-migration-*.tar.gz root@NEW_SERVER_IP:/root/

روی سرور جدید (اول نصب تمیز):
  wget .../install-v1.1.zip && unzip && cd personal-site && sudo ./install.sh
  sudo bash scripts/import-site.sh /root/site-migration-<timestamp>.tar.gz

import-site.sh:
  - دیتابیس رو با owner امن (ehsansite) نصب می‌کنه
  - .env رو MERGE می‌کنه (DATABASE_URL جدید می‌مونه؛ secretها و tokenهای
    قدیمی برمی‌گردن)
  - apply_schema.py اجرا می‌شه (heal کردن schema drift)
  - سرویس رو start می‌کنه و admin رو verify می‌کنه

چک‌لیست بعد از مهاجرت:
  □ Webhookها رو برای دامنه‌ی جدید ثبت کن (Bale/Telegram setWebhook)
  □ sudo certbot --nginx -d YOUR_DOMAIN
  □ دامنه‌ی جدید رو تو console گوگل reCAPTCHA اضافه کن
